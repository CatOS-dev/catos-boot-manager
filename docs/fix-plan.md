# CatOS Boot Manager 修复计划

来源：2026 年 11 月 7 日的源码审查。编号沿用审查报告，P0 为安全或数据风险，P1 为写错目标或核心功能不可用，P2 为边界问题，UX 为交互改进。问题判断来自源码调用链，未在真机上验证固件写入和启动结果。

每项修复单独提交，附带回归测试；完成后在此勾选并注明提交。

## P0 安全与数据风险

- [x] **P0-1 扫描时以 root 执行外部挂载系统中的程序**
  `BootRepair::mountedTargets()` 把 `/mnt`、`/run/media` 下的系统列为目标，扫描时对含 `/etc/catos/firmware-boot.conf` 的目标执行 `arch-chroot <目标> catos-firmware-boot-update --describe`。插入自动挂载的 U 盘后打开程序，即会以 root 运行其中的程序。
  验收：只读探测不执行任何目标系统中的程序；挂载目标的配置以数据方式读取，并拒绝符号链接越界。
- [x] **P0-2 只读命令超时以 SIGKILL 结束，可能残留挂载和子进程**
  `BootProbe::runReadOnly` 超时直接 `kill()`，包装器的清理逻辑和子进程都得不到处理。
  验收：只读命令不得经由 chroot 包装器运行；超时先发 SIGTERM，等待后再强制结束整个进程组。
- [x] **P0-3 新建固件项被插到 BootOrder 首位，悄悄改变默认启动**
  `firmware-add` 使用 `efibootmgr -c`，rEFInd 注册使用 `--create`，二者都会把新项放到 BootOrder 最前。`catos-firmware-boot` 使用 `--create-only` 并追加到末尾，行为不一致。
  验收：新建固件项不改变原有 BootOrder 的先后，只追加到末尾；默认项只能通过显式操作修改。

## P1 目标正确性与核心可用性

- [x] **P1-4** GRUB UEFI 固定 `--target=x86_64-efi` 与 `--bootloader-id=CatOS`；修复不沿用现有实例路径。按目标架构选择 target，修复时使用所选实例的 id。
- [x] **P1-4b** Limine 自动修复挂载所选 ESP，但 `limine-install` 仍使用工具配置的目标。目标不一致时提前拒绝，或向工具传递明确目标。
- [x] **P1-4c** 自动修复不挂载独立 `/boot`。按目标 fstab 挂载，或在写入前阻止。
- [x] **P1-5** 自动修复的 ESP 下拉列出所有分区，后端也只检查是分区。按 ESP 分区类型和 vfat 过滤，并在后端校验。
- [x] **P1-6** 已解锁的 LUKS（`crypt`）和 LVM 根设备被拒绝且没有说明。支持这两类设备，或给出明确提示。
- [x] **P1-7** 开启 Secure Boot 或状态未知时，引导方式页无法设默认或单次启动，UEFI 启动项页却可以。统一规则，并说明原因。
- [x] **P1-8** `BootPlan::firmwareConflict` 在 GUI 进程中以桌面用户读取 ESP 文件大小，ESP 以 `umask=0077` 挂载时所有实例都不可选。文件检查移至特权端，结果放入快照。`FirmwarePage` 的文件选择对话框同样受影响。
- [x] **P1-9** 发现逻辑不识别 `shim*.efi` 和 `EFI/BOOT/BOOT*.EFI`。Secure Boot 下的实例显示未注册，removable 安装无法识别。

## P2 边界问题

- [ ] **P2-10** BLS 条目有多行 `options` 时，编辑后只保留最后一行，丢失其余参数。
- [x] **P2-11** GRUB“上次选择的项”只写 `GRUB_DEFAULT=saved`，未设置 `GRUB_SAVEDEFAULT=true`。
- [x] **P2-12** Limine 删除当前默认项后，默认值静默回到第 1 项，没有提示。
- [x] **P2-13** GRUB 值中的单引号转义后读回不还原；带行尾注释的行无法解析。
- [ ] **P2-14** 软件包只按当前主机检查和安装，不检查修复目标系统；`pacman -S` 前不同步数据库。
- [x] **P2-15** 固件项改回原名后，操作不会自动撤销；不在 BootOrder 中的项无法加入顺序。
- [ ] **P2-16** 预检拒绝原因只写入日志，且大多未翻译；对话框只显示“执行前被拒绝”。
- [ ] **P2-17** 扫描对每个 `.efi` 文件依次运行 `bootctl` 与 `objdump`；预检和 rEFInd 注册各自再完整扫描一次；每个目标的配置读取两次。

## UX 与功能补齐

- [x] **UX-1** 审阅对话框展示菜单和配置的差异。
- [x] **UX-2** 提供备份恢复入口，说明可恢复范围。
- [x] **UX-3** 合并“部署、修复、更新”中行为相同的按钮，或明确区分各自效果。
- [x] **UX-4** 修复模式默认勾选“注册固件项”。
- [x] **UX-5** 按设计文档把“修复与恢复”“配置与更新”独立为左侧导航页。
- [x] **UX-6** 扫描显示进度；取消授权时提供只读模式，而不是直接退出。
- [x] **UX-7** 禁用的按钮通过提示说明原因。
- [x] **UX-8** 标注自动生成的菜单项（kernel-install、limine-entry-tool、快照包），提示编辑会在更新时被覆盖。
- [x] **UX-9** 安全启动页结构化展示 MOK 状态，并支持注册操作。
- [x] **UX-10** 特权端错误信息接入翻译。
- [x] **UX-11** 覆盖 fallback、BIOS 写整块磁盘等高风险操作需要二次确认，并写明受影响的磁盘或分区。
